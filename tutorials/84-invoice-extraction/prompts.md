P1 (new session, @thequantexplorer/product-demo-apps):
Follow the "Post-train a task model on Modal" playbook for a new task: invoice and receipt extraction in the invoice-extraction-modal folder. Start with step 1: set the folder up for Modal training jobs, verify Modal auth with the MODAL_TOKEN_ID / MODAL_TOKEN_SECRET secrets and save the setup as a skill. Use Modal app and volume names that start with invoice-extraction-. Only touch invoice-extraction-modal.

P2: Build the data from the OCR text of two receipt datasets: SROIE (github.com/zzzDavid/ICDAR-2019-SROIE, data/box + data/key: company, date, address, total) and CORD v2 (Hugging Face naver-clova-ix/cord-v2: line items with name, quantity, price, plus subtotal, tax, total). Keep one fixed JSON schema per dataset. Fixed-seed split with seed 42: 250 SROIE and 250 CORD receipts held out for test, everything else for training, each split in its own file. Write reward.py: field-level exact match after normalization (trim, dates to ISO, amounts to plain numbers), F1 over line items, plus a check that the line items add up to the total where they exist, and -0.5 for unparseable JSON. Unit-test it.

P3: Score field accuracy, whole-document exact match, p50 latency and cost per 1M documents on the test split, with one shared zero-shot prompt, for (a) gpt-6.1-sol (it only accepts the default temperature) and (b) Qwen/Qwen3.8-27B (thinking off) served with vLLM on a Modal H100 with an 8,192-token context. Save per-document results so we can run significance tests later. Write results.md.

P4: Write train_sft.py as a Modal app with checkpoints on a modal.Volume. LoRA SFT with TRL on the train split for one epoch on an H200, with a 4,096-token max length so no receipt or answer is cut off. Launch with modal run, watch the logs, fix anything that breaks, then re-run the eval.

P5: Write train_grpo.py: GRPO with TRL from the base model, using reward.py, on a Modal B200 (the 27B with colocated vLLM needs more than an H200's 141 GB). Start with learning rate 2e-5, LoRA rank 16, 8 generations per prompt, 250 steps. Track mean reward, then evaluate the checkpoint.

P6: Spin up 4 managed Devins for a GRPO sweep. First hold out 126 training receipts as a validation set and re-run the SFT recipe on the other 1,000, so validation stays unseen. Each Devin then runs one GRPO variant for 150 steps starting from that SFT checkpoint (learning rate, LoRA rank, number of generations per prompt, reward shaping). Collect the validation scores, with that SFT checkpoint as the reference, into a table, promote the best by validation, and only then score it on the 500 test receipts.

P7: Deploy the winning checkpoint as an OpenAI-compatible vLLM endpoint with modal deploy, behind an API key, scaling to zero. Add an EXTRACT_BACKEND setting so the demo app can call that endpoint, then show the app extracting the same CORD receipt with gpt-6.1-sol and with our endpoint in the browser, and record it.

P8: Fill in the final scorecard in results.md on the 500 test receipts (gpt-6.1-sol / base 27B / SFT / GRPO / sweep winner: field accuracy and document exact match with 95% paired-bootstrap confidence intervals, p50 latency, $ per 1M documents). Run paired tests between the deployed model and each other model (paired bootstrap on per-document field accuracy, McNemar on exact match, Holm correction), say which differences are statistically significant and what the cost numbers leave out, and open a PR.
