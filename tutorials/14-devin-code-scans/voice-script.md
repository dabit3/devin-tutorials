# Devin Code Scans — voice script

Narrated by Nader Dabit (ElevenLabs voice `T8iHhGIWPm2GVYpQD1Am`). Each line plays over the shot named on the left.

| Shot | Narration |
| --- | --- |
| Home screen | This is Devin Code Scans. Devin reads a whole repo, looking for one kind of issue, and then fixes what it finds. |
| Clicking the composer | In the composer, type slash scan. |
| Scan type menu | Pick a scan type, like accessibility, performance or dead code, or just describe what you want. |
| Typing the request | Say what to look for, and mention the repo. |
| Code scan setup card | Devin names the scan type, and sends a setup card to confirm before anything runs. |
| Repositories field | Check the repositories to scan, |
| Focus field | and what the scan should focus on. |
| Start scan | Then click Start scan. |
| Started a code scan | The scan runs in its own session, so you can keep working. |
| Findings tab, no findings yet | First, Devin reads the codebase. |
| Findings appear | Findings show up as soon as Devin confirms them. |
| Completed scan | This scan found seven accessibility issues, ranked by severity. |
| Hovering Scan new commits | Later, Scan new commits scans only the commits added since the last run. |
| Opening a finding | Open a finding to see the details. |
| Finding detail | Each one explains the barrier, who it affects, and where it is in the code. |
| Fix with Devin | Click Fix with Devin, |
| Fix session starts | and Devin starts a session to fix it. |
| Finding in PR open | When the fix is ready, the finding moves to PR open. |
| Inline PR | The pull request opens right inside the finding. |
| Diff | Devin added visible focus rings back to the filter controls and the command input. |
| GitHub link | Review it here, or open it on GitHub. |
| Outro | Scan a repo, then let Devin fix what it finds. |
